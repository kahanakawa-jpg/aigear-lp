営業リストのスコアリングは、プロンプト（AIへの指示文）に「各社を公開情報で調べてから、5つの基準で1〜5点をつけ、合計でS〜Dに分けろ」と書いておけば、AI（Claude）が調べる・採点する・並べ替えるところまでやります。この記事では、私が実際にClaudeのスキルとして保存し、自分の営業リストで使っているスコアリングプロンプトを全文公開します。あわせて、採点基準の書き換え方、スプレッドシートで回す手順、実際につまずいた失敗の直し方までまとめました。プロンプト自体はWeb検索ができる生成AIなら動きます（FAQ参照）。

営業リストのスコアリングで「当たる順番」が変わる理由

同じ100社の営業リストでも、上から機械的に当たるのと、受注確度の高い順に当たるのとでは、同じ工数で得られるアポの質が変わります。問題は、優先順位づけを人がやると1社あたり10〜15分の企業リサーチが必要になることです（私が手で調べていたときの体感です）。100社なら17〜25時間かかる計算です。だから多くの現場では「調べずに上から当たる」か「カンで選ぶ」ことになります。

検索すると「営業リストをAIで作る」記事は多く見つかりますが、作ったリストを「どの順で当たるか」に踏み込んだ記事はほとんどありません。リストの数を増やすより、手元のリストの順番を変えるほうが、明日の行動が変わります。

Anthropicの営業責任者が4,000社を一晩で採点した事例

この方法を試すきっかけになったのは、Claudeを開発するAnthropicの公式ブログ（2026年5月20日公開）です。同社の米国ミッドマーケット営業責任者（Head of US Mid-Market GTM）のTravis Bryant氏が、担当する4,000社のアカウントを、Claude Coworkで一晩のうちに全件スコアリングしたという内容でした。基準（ルーブリック）を2種類×5項目で定義し、各社について数値スコアと文章の根拠を出力させ、最後にダッシュボードにまとめています。出典は公式ブログです。

ただしAnthropic社内にはSalesforceやBigQueryの自社データがあり、中小企業のリストにはそれがありません。そこで私は「公開情報だけで採点する」形に翻訳し、自分のリストで試しました。違いは後の章で表にしています。

行動データを使うリードスコアリングとの違い

「リードスコアリング」で検索すると出てくるのは、資料請求や料金ページの閲覧、メール開封などの行動データに配点する方法です。これは、すでに自社と接点がある見込み客を対象にした仕組みで、行動データが溜まっていることが前提になります。

この記事で扱うのは、まだ接触していない企業のリストです。行動データはゼロなので、代わりに採用ページ・プレスリリース・ニュースなどの公開情報を根拠にします。中小企業の営業で「リストはあるが、どこから当たるか決まっていない」状態に向いているのはこちらです。

営業リストのスコアリングプロンプト全文（スキルとして保存している手順書）

私はこの指示文をClaudeのスキル（保存した手順書）として登録し、「スコアリングして」と一言でスプレッドシートのリストに走らせています。2026年6月12日に公開した実演動画では、8社のリストに対して、各社のホームページ・資金調達・プレスリリースのリサーチから採点、スプレッドシートへの書き込みまでを、4分38秒の動画の中で通しています。

社名など固有の情報は含まないので、そのまま載せます。自社用にするときに書き換えるのは、主に「自社の提供価値」の一文です。

プロンプト1: 手順書版（全文）

# 営業リストのスコアリング（手順書）

あなたはBtoB営業の戦略担当です。渡された営業リスト（企業名の一覧）の各社を公開情報でリサーチし、5基準で採点して優先度ランクを付けてください。

## 自社の提供価値（採点①「課題適合」の判断軸）
BtoB企業の営業活動＝商談記録・CRM入力・リスト管理・提案書作成などの事務作業をClaudeで自動化し、実装まで伴走する実行支援。
※ここだけ自社の一文に書き換える

## 入力
- 企業名のリスト（スプレッドシート、貼り付けテキスト、CSVのいずれか）
- あれば各社のURL・業種・従業員規模も受け取り、根拠の精度を上げる
- 共有元のスプレッドシートのURLがあれば、書き込み先として使う

## 手順1: リサーチ（各社）
Web検索で各社の次を調べ、出典URLを控える。
- 事業内容・ビジネスモデル（toB / toC）
- 規模（従業員数・上場/非上場・資本金）
- 直近の動き: 資金調達 / 採用増 / 出店 / 新規事業 / 大型リリース
- 同種ツール（営業支援SaaS・AI営業自動化）の導入有無
最低でも「会社概要」「業績/資金調達」「従業員数」の3観点を検索する。

## 手順2: 採点（5基準・各1〜5点）
各基準に必ず1行の根拠を付ける。根拠は調べた公開情報とリスト内の情報のみ。
確認できない事柄は「要確認」とし、推測で点を盛らない。事実が取れない基準は無理に高得点にしない。
1. 課題適合 … 上記の提供価値と、その会社の営業事務の痛みがどれだけ合うか（toC中心・営業組織が薄い→低／BtoB営業で商談記録・提案書作成の事務が多い→高。自社が営業支援SaaSベンダー等で内製・競合する場合は下げる）
2. 予算体力 … 従業員規模・事業形態・資金状況から見た投資余力（赤字/小規模→低、調達済/拡大期→高）
3. タイミング … 採用増・資金調達・出店・新規事業など、今動いている兆候があるか
4. 接触しやすさ … 決裁者への距離・既存接点・問い合わせ窓口やSNS露出の有無
5. 競合状況 … 同種ツール導入済みか（入替か新規か）。導入実態が不明なら根拠に「要確認」と明記

## 手順3: ランク付け（合計点 → S/A/B/C/D）
出力の冒頭に必ず各ランクの意味を明記する。
- S（23〜25） 今すぐ最優先で当たる
- A（19〜22） 優先的に当たる
- B（14〜18） 条件・タイミングを見極めて当たる
- C（10〜13） 中長期で再評価
- D（9以下） 今は見送り

## 手順4: メモ欄（理由＋次の打ち手）
各社2〜3文で、(a) なぜそのランクか、(b) 次の打ち手（いつ・どんな角度で当たるか）を書く。
例: 「資金は潤沢だが事業がtoC寄りで営業の痛みは薄い。半年後に拡大期の体制づくり文脈で再評価」

## 出力
1. 合計点の降順テーブル: 会社名｜各基準の点＋1行根拠｜合計点｜優先度ランク｜メモ
2. タブ区切りTSV（1行目が見出し）。列: 会社名 / ①課題適合(点) / ①根拠 / ②予算体力(点) / ②根拠 / ③タイミング(点) / ③根拠 / ④接触しやすさ(点) / ④根拠 / ⑤競合状況(点) / ⑤根拠 / 合計点 / 優先度ランク / メモ（理由＋次の打ち手）
3. 末尾に「要確認」の主な項目をまとめる
4. 出典を「Sources: [タイトル](URL)」形式で列挙する

## スプレッドシートへの書き込み（指定があれば）
- 別の場所に新しい表を作らず、リストに載っている各社名の隣（同じ行）に書き込む
- リストの並び順は変えない（合計降順に並べ替えない）。並べ替えが必要なら「合計点」列で降順ソートできる旨を提案する

## やってはいけないこと
- 確認できない事実に推測で点を付けること（→「要確認」にする）
- リストと別の場所に切り離した表を作ること（→各社名の隣に書く）
- 指定がないのに並び順を勝手に変えること

長く見えますが、中身は「調べる観点」「5基準の定義」「ランクの閾値」「出力の形」「禁止事項」の5つだけです。

5基準の定義文を自社用に書き換える

採点の質は、AIの賢さより「基準を言葉にできているか」で決まります。上の5基準は汎用形なので、自社の受注実績から翻訳してください。

基準点が高い例点が低い例
課題適合BtoB営業で商談記録や提案書の事務が多いtoC中心で営業組織が薄い
予算体力資金調達済み・拡大期小規模・赤字が続いている
タイミング採用増・出店・新規事業のリリース直近1年ニュースがない
接触しやすさ社長が発信している・問い合わせ窓口が明確大企業で窓口が見えない
競合状況導入の形跡なし（新規）導入事例として公開されている（入替）

翻訳の仕方は「過去に受注した会社の共通点」を基準の定義文に書き込むことです。私の場合、ITエンジニアに特化した人材紹介・SES・受託開発など、社長や営業責任者と直接話せる中小企業の受注率が高くなっています。そこで「自社の提供価値」の一文の末尾に「相性が良いのはITエンジニア特化の人材紹介・SES・受託開発などの中小BtoB」と1行足し、接触しやすさの定義文を「社長・営業責任者本人に届く経路があるか（問い合わせ窓口のみは3点まで）」のように厳しめに書いています。配点は5基準とも等しく1〜5点のままで、特定の基準を重くする計算はしていません。自社が「大企業の部門」を相手にしているなら、接触しやすさの定義は「担当部門の責任者名が公開されているか」に変わります。

プロンプト2: 一言版（スキルを作らない場合）

スキルを作らず、チャットにリストを添付して1回だけ回すならこちらです。手順書版を1本のメッセージに圧縮したもので、スキル機能が無い環境やChatGPTで回すときはこちらを貼ってください。

あなたはBtoB営業の戦略担当です。
添付の営業リスト各社について、まず各社の最新の公開情報（事業内容・規模・直近の動き＝資金調達/採用/出店/新規事業など）をWebで調べてください。
その上で、下記5基準で1〜5点で採点し、合計点の高い順に並べ替えてください。
各基準の点数には必ず1行で根拠を書いてください（調べた公開情報・リスト内の情報のみを根拠に。確認できない事柄は「要確認」とし、推測で点を盛らないこと）。

【採点基準】
1. 課題適合（自社の提供価値: BtoB企業の営業活動＝商談記録・CRM入力・リスト管理・提案書作成などの事務作業をClaudeで自動化し実装まで伴走する実行支援、とどれだけ合うか）
2. 予算体力（従業員規模・事業形態から見た投資余力）
3. タイミング（採用増・資金調達・出店・新規事業などの動きがあるか）
4. 接触しやすさ（決裁者への距離・既存接点の有無）
5. 競合状況（同種ツール導入済みか＝入替/新規）

【出力】
- 合計点の降順テーブル（会社名｜各基準の点と1行根拠｜合計点｜優先度ランク｜メモ）
- 優先度ランクは合計点をもとに S / A / B / C / D の5段階に振り分け、各ランクの意味（例: S=今すぐ当たる / D=今は見送り）も冒頭に明記すること
- 「メモ」欄には、点数の理由（なぜそのランクか）に加えて「次の打ち手（いつ・どんな角度で当たるか）」を2〜3文で書くこと。例: 「資金は潤沢だが事業がtoC寄りで営業の痛みは薄い。半年後に拡大期の体制づくり文脈で再評価」
- 上記テーブルを、スプレッドシートにそのまま貼り付けられるタブ区切り形式（1行目は見出し）でも出力すること
事実が確認できない項目は無理に点をつけず「要確認」とすること。

2本に共通する4つの仕掛け（抜くと何が起きるか）

どちらのプロンプトにも、次の4つが入っています。自社用に書き換えるときも、ここは残してください。

仕掛けプロンプトでの該当箇所抜くと起きること
採点の前に調べさせる「まず各社の最新の公開情報をWebで調べてください」社名の印象だけで点がつく。根拠のない点数（ハルシネーション）になる
1行の根拠を必須にする「各基準の点数には必ず1行で根拠を書いてください」なぜその点かが分からず、現場が点数を信用しない
不明は「要確認」「確認できない事柄は『要確認』とし、推測で点を盛らないこと」情報が少ない会社ほど点が盛られる
メモ欄に次の打ち手「いつ・どんな角度で当たるか」順番は決まるが、一通目の切り口が決まらず結局止まる

スプレッドシートで営業リストのスコアリングを回す手順

ステップ1: 社名の一覧を用意する

列は最低限で構いません。

  • 会社名（必須）
  • 業種・従業員規模・所在地（あれば精度が上がる）
  • 自社との接点（過去の問い合わせ有無など）

「直近の動き」のような調査が必要な列は空欄で構いません。そこはAIにリサーチさせます。私はGoogleスプレッドシートを共有するだけですが、CSVやテキストの貼り付けでも同じプロンプトで動きます。

ステップ2: 「スコアリングして」と一言で走らせる

スキルとして保存してあれば、シートのURLを貼って「スコアリングして」と書くだけで手順書が走ります。実演でも、全社のリサーチが終わってから採点が始まり、合計点とランク、「どういう切り口で打診するか」の一言までがシートに書き込まれました。

手順書版・一言版のどちらでも、出力の形（例）は次のとおりです。数値と社名は形を示すための作例です。

会社名課題適合予算体力タイミング接触しやすさ競合状況合計ランクメモ
A社5（BtoB営業中心・提案書業務が多い）4（直近で資金調達を公表）4（営業職の採用を強化中）4（社長がSNSで発信）要確認（導入実態が不明）17＋要確認B営業拡大期で事務が増える局面。採用強化の文脈で「入社した営業の事務を減らす」角度で接触

「要確認」が混ざった合計は、ランクの根拠が弱いことを示します。上の例なら、競合状況が5点ならAランクに上がるので、商談前に確認する項目として扱います。

ステップ3: 各社の隣の行に書き込ませる

私は点数とランクを各社名の隣（同じ行）に書き込ませ、並び順も変えさせません。理由は後述の失敗4に書きます。

書き込みは、私はブラウザ操作の拡張（Claude in Chrome）かスプレッドシートのコネクタで行っていますが、出力されたタブ区切りのTSVをコピーしてシートに貼るだけでも同じ形になります。ツールを増やさなくても運用できます。

ステップ4: ランクで当たり方を変える

スコアリングの効果は「全社に同じ熱量で当たらない」と決めたときに出ます。

  1. 1. S・Aランクは1社ずつ、メモ欄の切り口をもとに個別の仮説を持って当たる（フォームでもメールでも、企業ごとに一通目を変える）
  2. 2. Bランクはフォーム営業やメールでまとめて接触し、反応があった会社だけ深掘りする
  3. 3. C・Dランクは今期は追わない。リストからは消さず、次の再採点で拾い直す

S・Aランクへの一通目は、採点結果のメモ欄をそのまま材料にします。私は採点が終わった同じチャットに、続けて次の一言を投げています。

S・Aランクの各社について、メモ欄の切り口をもとに、最初の一通（問い合わせフォーム用・300字以内）の書き出しを1社1案ずつ書いて。売り込みではなく、相手の直近の動き（採用・調達・出店）に触れる角度で。根拠にした公開情報のURLも添えて。

出てきた文はそのまま送らず、根拠のURLを開いて事実を確認してから直します。ここを飛ばすと、古いプレスリリースを「直近の動き」として書いてしまいます。

スコアリングでつまずいた5つの失敗と直し方

実際に自分のリストで回して起きたことと、プロンプトや運用でどう直したかです。

1. 公開情報が少ない会社ほど点が盛られる

情報が少ない会社は、指示がないとAIが「〜と思われる」で埋めて中間点をつけてしまいます。直し方は、プロンプトに「確認できない事柄は『要確認』とし、推測で点を盛らないこと」を入れることでした。要確認が出るようになってから、点数の空白が「商談で聞くべきこと」に変わり、ランクの信頼度も読めるようになりました。

2. 資金調達の1基準に引っ張られる

資金調達を公表した会社は、予算体力とタイミングで高得点になり、合計が上がります。ただ、資金があることと、自社サービスの良い顧客であることは別です。事業がtoC寄りなら営業事務の痛みは薄く、課題適合は低くなります。5基準を合計で見る設計にし、メモ欄に「なぜそのランクか」を書かせているのは、1つの派手な情報に引っ張られないためです。「資金は潤沢だが事業がtoC寄り」の但し書きがあれば、人が読んだときに補正できます。

3. 競合状況は外から分からないことが多い

同種のツールを入れているかは、導入事例として公開されていない限り公開情報からは分かりません。そこで競合状況は「導入実態が不明なら根拠に『要確認』と明記」とし、商談の最初に聞く項目に回しました。スコアリングで決めきらない基準を1つ残しておくと、初回商談の質問が自然に決まります。

4. 別の場所に表を作られる・並び順が勝手に変わる

指示を入れないと、AIは新しいシートに合計順の表を作ります。見た目はきれいですが、元のリストと突き合わせる手間が発生し、既存の管理列（担当者・ステータスなど）と分断されます。「各社名の隣に書く」「並び順は変えない」を禁止事項に明記してから、この手戻りはなくなりました。

5. 点数が古くなる

タイミングの点数は鮮度が命です。資金調達や採用強化は数か月で状況が変わります。私は月1回など決めた周期で再採点し、前回とランクが変わった会社だけ見る運用にしています。「上がった会社」が今期の追加ターゲット、「下がった会社」が追客をいったん止める会社です。

スコアリングの前に、表記ゆれと重複を先に潰す

展示会・問い合わせフォーム・名刺・手入力が混ざったリストは、同じ会社が「株式会社サンプル商事」「(株)サンプル商事」の2行で入っていることがあります。このまま採点すると、同じ会社を2回調べて2回採点し、最悪の場合2人の営業が同じ会社に当たります。スコアリングの前に、整形と名寄せ（同じ会社をまとめること）を先にやってください。

私が使っている前工程のプロンプトです。2026年6月24日に公開した「汚いリードリストの整形」の実演動画で使ったものと同じで、スコアリングと同じくClaudeとGoogleスプレッドシートだけで動きます。

① クレンジング（表記ゆれ・欠損をそろえる）
これは展示会・問い合わせフォーム・名刺・手入力が混ざった私のリードリストです。営業で使える台帳に整えてください。

【やること】
1. 会社名を正規化する：法人格（株式会社／(株)／㈱／カ）／会社）の表記を「株式会社◯◯」に統一。前後の空白を除去。
2. 氏名を正規化する：姓名の間は半角スペース1つに統一。全角英数・半角カナは通常表記へ直す。役職も表記をそろえる。
3. メール（全角＠や大文字小文字）・電話番号を、決めたフォーマットに統一（電話は「0X-XXXX-XXXX」）。
4. 欠損・不備（空欄／「-」「不明」「※後で確認」／明らかに壊れたメール）は、勝手に埋めず「要確認」列を立ててフラグを立てる。

整えた結果を表で出して。推測で埋めた箇所があれば必ず「要確認」と明記すること。

② 重複・名寄せ（同じ会社をまとめる）
①で整えたデータから、同一企業・同一人物の重複を見つけてまとめてください。

- 会社名の表記ゆれ（例：「株式会社サンプル商事」「(株)サンプル商事」「サンプル商事㈱」）は同一企業として名寄せする。
- 電話番号やメールドメインが一致する行は、社名表記が違っても同一候補として提示して。
- 同じ会社に複数の担当者がいる場合は、会社1行にまとめ、担当者を併記する形に整える。
- 「同一の確信度（高/中/低）」と、そう判断した根拠（一致した項目）を添えること。確信が持てないものは統合せず候補として残す。

統合後の社数・名寄せした件数・統合前後の行数を最後にまとめて。

ここでも「勝手に埋めない」「確信が持てないものは統合しない」を入れています。名寄せの最終判断は人がやり、整形が終わった台帳をスコアリングにかける、という順番です。

名刺・フォームの個人情報を貼る前に

上の整形プロンプトは、氏名・メールアドレス・電話番号という個人情報を扱います。実データを貼る前に、次の3点を確認してください。

  • 入力を学習に使わない状態にする。Claudeの個人向けプラン（無料・Pro・Max）は既定で学習利用がオンなので、設定 → プライバシー →「AIモデルの改善にご協力ください」をオフにします。Team/Enterprise などの法人プランは既定で学習に使われません。設定を確認するまでは実データを貼らないでください。他のツールで回す場合も、同じくデータ管理の学習オフを先に確認してください。
  • 最初は架空データで挙動を確かめる。2026年6月24日の実演も、汚れ方を再現した架空32行のリストで通しています。
  • スコアリング用のリストは社名・業種・規模だけでも精度はほとんど落ちません。採点の根拠は公開情報なので担当者名は不要で、「自社との接点」列も「有／無」だけにしています。

専用ツール・CRM内蔵AI・生成AI×スプレッドシート、どれで組むか

スコアリングを実装する方法は、大きく3つあります。この記事の方法は3つ目です。

方法向いている会社根拠にするデータ費用感
営業リスト作成ツールの企業スコアリストの母数をこれから増やす会社ツール側が持つ企業データ（求人・ニュース・活発度）月額数万円〜
CRM内蔵のAIスコアリング見込み客の行動データがCRMに溜まっている会社ページ閲覧・メール開封・商談履歴CRMの上位プラン
生成AI×スプレッドシート（この記事）手元のリストの順番を今すぐ決めたい会社公開情報＋リスト内の情報Claudeの月額プランのみ

ツールの企業スコアは「その会社が活発かどうか」を測るもので、「自社に合うか」は測りません。CRM内蔵のスコアは行動データがないと動きません。どちらも持っていない状態から始められるのが3つ目です。リストが数千件になり、毎週の新規分を自動で採点したくなった段階で、定期実行（Cowork等）やツール連携を考えれば足ります。

採点結果を現場が信用するために

スコアリングが形骸化する一番の原因は「点数の理由が見えないこと」です。根拠なしの点数は、ベテランほど信用しません。対策は2つです。

  • 1行根拠とメモ欄を、点数と同じ行に必ず置く。「なぜB」が読めれば、納得しなくても反論できる
  • 人が根拠を読むのは上位の2〜3割だけでよい。全件を読み直す運用にすると続きません

効果の測り方は、ランク別に「接触数に対する商談化率」を四半期ごとに比べることです。S・AがB以下より高ければ基準は機能しています。差が出なければ、基準の定義文が自社の受注パターンとずれているので、直近の受注先の共通点を定義文に書き戻します。私はこの記事で目標値は書きません。自社で測っていない数字を書くと、それ自体が「根拠のない点数」になるからです。

リストの次は「当たった後」を自動化する

優先順位をつけたリストに当たり始めると、次に詰まるのは商談後の処理です。商談が入ったら商談の議事録をAIで自動化する手順で議事録づくりとCRM入力を一度に済ませ、商談後のお礼メールと、返信が止まった案件への追いメールは営業メールの返信をAIで下書きする方法の型で下書きします。提案まで進んだら営業の提案書をAIで作成する手順につながります。

よくある質問

ChatGPTでも同じプロンプトで動きますか？

動きます。条件は、Web検索ができるモードを使うことです。この方法は「採点の前に公開情報を調べる」ことが前提だからです。Claude・ChatGPT・Geminiのいずれでも、検索を有効にしたうえで一言版のプロンプトを貼ってください。

何社くらいのリストまで対応できますか？

実演では8社、私の普段の運用では20〜30社ずつ回すことが多いですが、仕組み上は数百社でも同じ指示で回ります。1社ずつWeb検索するため、件数に比例して時間がかかります。件数が多い場合は「まず全社を簡易採点→S・Aだけ深掘りリサーチ」の2段構えにすると、時間と精度のバランスが取れます。

採点結果はどこまで信用していいですか？

「当たる順番を決める道具」としては十分ですが、点数の根拠は必ず見てください。公開情報が古いことがあるためです。根拠の1行に公開情報の日付（「2026年3月のプレスリリース」など）を含めさせると、古い根拠を人が一目で弾けます。「要確認」がついた基準は商談で聞く、という運用にすれば、確認工数を最小にしながら誤爆を防げます。

そもそも営業リストが無い場合はどうすればいいですか？

過去に受注した会社を5社ほど渡して「似た会社を50社挙げて」と頼み、出てきた候補を同じプロンプトで採点する、という順番で作れます。ただしAIが挙げた会社の連絡先は必ず公式サイトで確認してください。社名は合っていても、電話番号やメールアドレスは誤っていることがあります。
